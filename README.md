# IZLA

Пилотная платформа услуг для Узбекистана: React + Vite, Express, PostgreSQL. Один Docker-сервис отдаёт интерфейс и API; отдельный PostgreSQL хранит данные. Это веб-приложение/PWA для мобильных браузеров и компьютеров, не нативный APK/IPA.

## Реализовано

- Роли клиент/исполнитель; администратор назначается только по `ADMIN_TELEGRAM_IDS`.
- Telegram-вход: временный запрос, контакт самого Telegram-пользователя, точное совпадение номера, одноразовый код, привязка к браузеру, лимит попыток, HttpOnly cookie.
- Каталог, категории, город, поиск, сортировка, избранное, объявления исполнителей и комментарии.
- Заявки с обязательным фото и описанием; для доставки — состав, два адреса, контакт получателя. Получатель видит заказ после входа со своим номером.
- Состояния заказа и блокировка переходов на сервере. Принять заказ может только проверенный исполнитель; операция защищена транзакцией и блокировкой строки PostgreSQL.
- Подтверждение передачи отправителем; фото и описание курьера до начала и при завершении; слайдеры подтверждения.
- Чат, история, рейтинг и один отзыв от клиента на завершённый заказ.
- Споры, блокировка пользователей, скрытие объявлений, ручная проверка документов, журнал действий администратора и JSON-экспорт дела с хешами фотографий.
- Съёмка через `getUserMedia`, без выбора файла в штатном интерфейсе. Это не гарантирует аппаратную подлинность камеры и не является liveness-проверкой.
- Фотографии заказов зашифрованы AES-256-GCM. HTTP-доступ только участникам или администратору. Документы проверки личности хранятся в отдельной базе.
- Яндекс Карты: адаптер JS API, маршрут, оценка времени и текущая точка курьера. Необходим ключ с разрешёнными доменами и подходящая лицензия.
- Геолокация по согласию в активном заказе, обновление экрана раз в 5 секунд. Браузер не гарантирует GPS в фоне/при заблокированном экране. Для фонового курьерского режима потребуется нативный клиент.
- RU / UZ / EN, светлая и тёмная темы, адаптивный интерфейс, reduced-motion, контакты поддержки.
- Предварительные правила и политика конфиденциальности. Нет фиктивных исполнителей, отзывов, платежей или успешных проверок MyID.

## Локальная разработка

Node.js 22 LTS:

```bash
npm ci
npm run check
npm start
# В другом терминале при разработке интерфейса:
npm run dev
```

`npm run build` создаёт интерфейс; `npm start` запускает порт 3000. Без `DATABASE_URL` в непродуктивной среде используется **временная** in-memory база pg-mem. Локальные тестовые роли доступны в окне входа. В `NODE_ENV=production` тестовый маршрут отсутствует, требуется настоящая PostgreSQL и ключ шифрования. Не используйте тестовые роли для публичного запуска.

## Railway

1. Создать сервис из этого репозитория, ветка `main`. Railway использует Dockerfile.
2. Создать PostgreSQL с постоянным томом.
3. Установить `DATABASE_URL=${{Postgres.DATABASE_URL}}`, `NODE_ENV=production`, `DATA_ENCRYPTION_KEY` (64 hex-символа), `PORT=3000`.
4. Создать публичный домен и установить `APP_ORIGIN=https://домен`.
5. Проверить `/api/health`: `status: ok`, `database: connected`.

Секрет шифрования генерируется командой:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Храните резервную копию ключа отдельно: его потеря делает фотографии нечитаемыми. Не заменяйте ключ без миграции данных. Включите резервное копирование PostgreSQL и проверьте восстановление до приёма реальных заказов. Приложение рассчитано на одну реплику; rate-limit хранится в памяти процесса. Для масштабирования нужен общий Redis limiter и распределённые события.

## Что нужно подключить до открытия регистрации

### Telegram

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без @), `TELEGRAM_WEBHOOK_SECRET` и числовой Telegram ID владельца в `ADMIN_TELEGRAM_IDS`. Имя `@i0000001i` — контакт поддержки, не токен бота и не числовой ID.

Настроить webhook скриптом `node scripts/telegram-webhook.mjs` в доверенной среде с переменными окружения. Никогда не публиковать токен в git или сообщениях поддержки. Числовой ID администратора должен быть настроен **до первого входа** владельца. Для изменения роли уже зарегистрированного владельца нужна отдельная контролируемая миграция.

### Проверка личности

**MyID пока не интегрирован:** интерфейс явно показывает «Не подключено». Нужны договор, API/SDK и параметры конкретной схемы MyID; нельзя имитировать подтверждение локальной кнопкой. Документация: https://docs.myid.uz/ .

Ручная проверка реализована отдельно, но по умолчанию отключена. Для включения нужны `MANUAL_KYC_ENABLED=true` и `KYC_DATABASE_URL` — PostgreSQL на физическом сервере в Узбекистане. Клиент снимает документ с двух сторон и лицо в трёх ракурсах; модератор записывает решение и обоснование. Это не автоматическое распознавание подделок и не замена MyID. Приложение не может само проверить физическую юрисдикцию переданного URL.

База Railway в зарубежном регионе не предназначена для хранения биометрии. Закон в редакции 27.03.2026: https://lex.uz/ru/docs/8104580 . Условия обработки прочих персональных данных за рубежом также нужно подтвердить до регистрации пользователей. Правовые страницы являются проектом: перед публичным запуском указать юридического оператора, правовые основания, конкретные сроки хранения/удаления, порядок обращений и проверить соответствие с местным специалистом. Автоматическая очистка KYC и поток удаления аккаунта ещё не реализованы; не открывать массовый приём документов до их настройки.

### Карты

Установить `YANDEX_MAPS_KEY`, разрешить домен приложения в кабинете Яндекса, проверить условия тарифа и покрытие нужных городов Узбекистана. Без ключа приложение показывает адреса, а не выдуманный маршрут или ETA. Реальная интеграция с Яндексом не проверена без ключа.

### Оплаты и нативные приложения

В текущем пилоте стороны согласуют оплату напрямую. Нет приёма платежей, комиссии, эскроу и автоматических возвратов. GitHub Actions собирает веб-приложение, не APK/IPA. Для магазинов и стабильного фонового GPS нужен отдельный нативный этап.

## Проверка качества

`npm run check` проверяет синтаксис, запускает тесты и собирает production frontend. В `.github/workflows/ci.yml` та же проверка работает с настоящим PostgreSQL 17 на GitHub Actions, затем сохраняет артефакт `izla-web-build`.

Проверяются: полный цикл доставки, обязательность фото, роли, изоляция доказательств, одноразовые отзывы, спор и его повторное закрытие, защита CSRF, совпадение Telegram-контакта с аккаунтом, одноразовый код, браузерная привязка, шифрование и запрет неподдерживаемых изображений. Доступ к реальному Telegram в тестах заменён локальной заглушкой.
